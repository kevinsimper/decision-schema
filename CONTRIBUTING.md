# Contributing

Decision Schema is an early public draft maintained by Kevin Simper. Concrete examples and implementation experience are especially useful.

Open an issue describing the operational situation, the records you would write, and what the current specification cannot express or leaves ambiguous. Use fictional data. Explain whether the proposal changes the shared model or belongs in domain-specific payloads or implementation guidance.

For a pull request:

1. Explain the problem and proposed behavior.
2. Update the normative specification, relevant examples, and revision history together.
3. Distinguish requirements from recommendations and implementation choices.
4. Check references, table fields, decision chains, review behavior, and task lifecycles against the examples.
5. Describe compatibility implications for existing implementations.

The current `0.1.md` may receive draft corrections before 1.0; all substantive changes belong in the revision history. A new incompatible published version receives a new versioned file. `spec.md` points to the current version. Tags preserve each published snapshot.

By submitting a contribution, you offer it under the repository's [Apache-2.0 license](LICENSE), as described in that license's contribution terms. No separate contributor agreement is required.
